# AI評価プロンプト仕様

この文書は `sdd_spec.md` の AI評価機能を実装するためのプロンプト仕様です。Gemini API は Unity WebGL から直接呼ばず、Supabase Edge Functions などのサーバー側から呼び出します。

## 1. 目的

開発セッション終了時に入力された開発目標、達成度、振り返り、次のタスク、過去の直近記録を評価し、ゲーム内成長に使える定量評価と短評を返す。

AI評価は承認確定ではない。メンター承認後に正式なEXP、ランキング、ステータスへ反映する。

## 2. 入力

| 項目 | 説明 |
|---|---|
| goal | 開発開始時に入力した目標 |
| achievement_rate | 達成度。0から100の整数 |
| reflection | 開発終了時の振り返り |
| next_task | 次にやるタスク |
| duration_minutes | 開発時間 |
| recent_sessions | 過去の直近記録。継続性の評価に使う |

## 3. 出力

GeminiにはJSONのみを返させる。Markdown、説明文、コードフェンスは返させない。

```json
{
  "total_score": 82,
  "axis_scores": {
    "goal_achievement": 80,
    "specificity": 85,
    "learning": 78,
    "next_action": 90,
    "continuity": 75
  },
  "feedback": "目標に対する進捗と次回作業が具体的です。詰まった点の学びも少し足すとさらに良くなります。"
}
```

## 4. 評価軸

| キー | 評価軸 | 観点 |
|---|---|---|
| goal_achievement | 目標達成度 | 目標に対して何ができたかが明確か |
| specificity | 記録の具体性 | 何を作った、直した、試したか分かるか |
| learning | 学び・気づき | 詰まった点、学び、改善点が書かれているか |
| next_action | 次回行動 | 次にやることが具体的か |
| continuity | 継続性 | 前回の内容とつながっているか |

各スコアは0から100の整数にする。

## 5. ランク変換

AIレスポンスにはランクを含めなくてよい。アプリケーション側で `total_score` から変換する。

| ランク | スコア | EXP倍率 |
|---|---:|---:|
| S | 95-100 | 2.0 |
| A+ | 85-94 | 1.8 |
| A | 75-84 | 1.6 |
| B | 60-74 | 1.3 |
| C | 40-59 | 1.0 |
| D | 0-39 | 0.8 |

## 6. システムプロンプト

```text
あなたはプログラミングスクールの開発ログを評価するメンター補助AIです。
目的は、メンバーの自宅開発を継続しやすくするために、記録の質を公平に評価し、短い改善フィードバックを返すことです。

重要な制約:
- AI評価だけで承認確定しない。
- メンター承認前提の参考評価として扱う。
- 開発時間が長いだけで高評価にしない。
- 開発時間が短くても、具体的な学びや次回行動があれば適切に評価する。
- 本名、顔写真、個人情報の入力を求めない。
- 返答はJSONのみ。Markdown、コードフェンス、説明文を含めない。

評価軸:
- goal_achievement: 目標に対して何ができたかが明確か。
- specificity: 何を作った、直した、試したか分かるか。
- learning: 詰まった点、学び、改善点が書かれているか。
- next_action: 次にやることが具体的か。
- continuity: 過去の直近記録とつながっているか。

出力JSON:
{
  "total_score": 0から100の整数,
  "axis_scores": {
    "goal_achievement": 0から100の整数,
    "specificity": 0から100の整数,
    "learning": 0から100の整数,
    "next_action": 0から100の整数,
    "continuity": 0から100の整数
  },
  "feedback": "120文字以内の日本語の短評"
}
```

## 7. ユーザープロンプトテンプレート

```text
次の開発ログを評価してください。

開発目標:
{{goal}}

達成度:
{{achievement_rate}}%

開発時間:
{{duration_minutes}}分

振り返り:
{{reflection}}

次のタスク:
{{next_task}}

過去の直近記録:
{{recent_sessions}}

JSONのみで返してください。
```

## 8. バリデーション

AIレスポンスを保存する前に、次を検証する。

- JSONとしてパースできる。
- `total_score` が0から100の整数である。小数、文字列、`null` は不正とする。
- `axis_scores` に `goal_achievement`, `specificity`, `learning`, `next_action`, `continuity` の5つのキーがすべて存在する。
- 各軸スコアが0から100の整数である。小数、文字列、`null` は不正とする。
- `feedback` が空でない。
- `feedback` が長すぎる場合は保存前に切り詰める。

## 9. フォールバック

Gemini API失敗、JSONパース失敗、スキーマ不正の場合は、記録保存を失敗させない。失敗種別ごとに次の分岐で扱う。

| 失敗種別 | 例 | 処理 |
|---|---|---|
| 一時的な通信失敗 | Gemini API timeout、HTTP 5xx、network error | ステータスをAI評価待ちにし、指数バックオフで再試行キューへ入れる |
| 応答形式の失敗 | JSONパース失敗、必須キー不足、スコア型不正 | ヒューリスティックな暫定評価を保存し、validation_errorフラグを残す |
| 入力不足 | goal、reflection、next_task などの必須入力不足 | ヒューリスティックな暫定評価を保存し、メンター確認対象にする |

どの分岐でも、元エラー、選択した分岐、対象セッションIDをログに残す。

フォールバック時の短評例:

- `AI評価失敗のため暫定評価です。記録は保存されました。`
- `Gemini応答の形式が不正なため暫定評価です。`
- `目標・振り返り・次回タスクをもう少し具体化すると伸びます。`

## 10. テスト観点

- 具体的なログが高い `specificity` を得る。
- 次回行動が曖昧なログは `next_action` が低くなる。
- 過去記録とのつながりがあるログは `continuity` が高くなる。
- 達成度0%でも学びが具体的なら一律最低評価にしない。
- 達成度100%でも振り返りが短すぎる場合は高評価にしすぎない。
- AI失敗時に開発ログが失われない。
