# Attack On Rasshiine 運用マニュアル

この文書は `sdd_spec.md` の運用、エラーハンドリング、監査、セキュリティ要件を、週次運用で確認できる手順に整理したものです。

## 1. 役割

### メンター

- メンバー、メンターアカウントを作成する。
- 開発ログを確認し、承認、修正承認、却下を行う。
- 不審ログと未完了セッションを確認する。
- 実績申請を承認、却下する。
- ボスHPとボス戦設定を調整する。
- 不適切なプロダクトURLを非公開にする。

### メンバー

- 自分の開発セッションを開始、終了、修正する。
- 達成度、振り返り、次のタスクを入力する。
- 実績申請とプロダクトURL登録を行う。
- ボス戦に参加し、役割、武器、行動を選択する。

## 2. 初期セットアップ

1. Supabaseプロジェクトと必要なDBスキーマが作成済みであることを確認する。
2. Gemini APIキーがSupabase Edge Functions側にのみ設定されていることを確認する。
3. Unity WebGLクライアントにAPIキーや秘密情報が含まれていないことを確認する。
4. メンターアカウントを作成する。
5. 班と担当メンターを登録する。
6. メンバーアカウントを作成し、仮パスワードを一度だけ共有する。
7. 初回ログイン時にパスワード変更が求められることを確認する。

## 3. 日次運用

### 開発ログ確認

1. メンターダッシュボードを開く。
2. 承認待ち一覧を確認する。
3. 不審ログフラグがあるログを優先して確認する。
4. 目標、達成度、振り返り、次のタスク、AI評価を確認する。
5. 必要に応じてコメントを入力する。
6. 承認、修正承認、却下のいずれかを実行する。

### 承認判断

- 承認: 記録内容と開発時間が妥当で、成長反映してよい場合。
- 修正承認: 開発時間や入力値に軽微な修正が必要だが、成長反映してよい場合。
- 却下: 記録として不適切、または開発実態が確認できない場合。

承認済みログだけをEXP、ランキング、ステータス、ボス戦力に反映する。却下されたログは成長に反映しない。

### 不審ログ確認

次のフラグが付いたログは内容を確認する。フラグだけで自動却下しない。

| 条件 | フラグ |
|---|---|
| 1セッションが3時間以上 | 長時間セッション |
| 振り返りが3文字以下 | 振り返り不足 |
| 開発目標が3文字以下 | 目標不足 |
| 次のタスクが3文字以下 | 次回内容不足 |
| 達成率0%かつ開発時間が長い | 要確認 |
| 達成率100%が連続しすぎる | 要確認 |
| 1日合計8時間以上 | 要確認 |

### 未完了セッション確認

開始から3時間以上経過し、終了操作がないセッションは未完了として扱う。本人またはメンターが後から修正し、承認されるまでEXPとランキングには反映しない。

## 4. 週次ボス戦運用

### 事前準備

1. 対象週の承認済みログが反映済みであることを確認する。
2. 週次戦力を確認する。
3. ボスHPを確認し、必要に応じて調整する。
4. ボス戦の開始時刻をメンバーに共有する。
5. 前に映す画面が教室の距離から読めることを確認する。
6. メンバー参加画面で役割、武器、行動選択ができることを確認する。

### ボスHPの基準

```text
週次戦力 W = Σ（承認済み開発分 × AI倍率 × 役割貢献補正）
中ボスHP = 2.5 × W
ラスボスHP = 7.5 × W
```

実際のHPはメンターが調整できる。ボスHPは翌週へ持ち越さない。負けても努力報酬は付与できる。

### 実施中

1. メンターがボス戦を開始する。
2. 各ターンでメンバーが行動を選択する。
3. ターン終了時に行動集計、ダメージ、回復、支援効果を確認する。
4. 前に映す画面でボスHP、チーム総ダメージ、残りターン、注目貢献者を表示する。
5. 通信断のメンバーがいても、ボス戦全体は継続する。

### 実施後

1. 勝敗結果を確認する。
2. 個人貢献とチーム総ダメージを確認する。
3. 必要な報酬や実績反映を確認する。
4. 次週に持ち越してはいけないボスHPや一時状態が残っていないことを確認する。

## 5. 実績とプロダクトURL

### 実績申請

メンバーは大会提出、プロダクトリリース、プロダクトアップデート、大会受賞、継続開発を申請できる。メンターは内容を確認し、承認または却下する。

承認後に付与するもの:

- 特殊武器
- 称号
- スキル解放

### プロダクトURL登録

メンバーはプロダクト名、URL、説明を登録できる。メンター承認は不要だが、不適切URLはメンターが非公開にできる。

公開時の注意:

- 本名を表示しない。
- 画像アップロードは扱わない。
- 不適切URLを見つけた場合は非公開化し、監査ログに残す。

## 6. エラー対応

| ケース | ユーザー表示 | 運用対応 |
|---|---|---|
| ログイン失敗 | IDまたはパスワードが違います | ログインID、有効状態、初回パスワード変更状態を確認する |
| 開発ログ保存失敗 | 保存できませんでした | 再試行し、保存されていない場合はメンバーに再入力を依頼する |
| AI評価失敗 | AI評価待ちです | 記録が保存されていることを確認し、後で再実行する |
| 承認失敗 | 承認できませんでした | 二重承認、権限、通信状態を確認して再試行する |
| ボス戦中の通信断 | 再接続中です | ボス戦は継続し、復帰後に状態同期を確認する |
| 行動未選択 | 時間切れです | 通常攻撃または待機として扱われたことを確認する |
| 未完了セッション | 終了されていないセッションがあります | 本人またはメンターによる修正へ誘導する |
| 不審ログ検出 | 要確認ログがあります | メンターが内容確認し、承認判断する |

## 7. 監査ログ

次の操作は監査ログに残す。

- ログイン
- アカウント作成
- パスワード変更
- 開発ログ作成
- 開発ログ編集
- 承認
- 修正承認
- 却下
- 実績承認
- ボスHP変更
- URL非公開化

監査ログには、操作者、操作種別、対象種別、対象ID、変更前、変更後、操作日時を記録する。

## 8. セキュリティ運用

- パスワードはハッシュ化して保存する。
- 仮パスワードは一度だけ表示する。
- 初回ログイン時にパスワード変更を促す。
- Gemini APIキーをUnity WebGL側に置かない。
- Gemini API呼び出しはSupabase Edge Functions経由にする。
- 本名、顔写真、画像アップロードを扱わない。
- ランキングはニックネームのみ表示する。
- ランキング非表示設定を尊重する。
- メンター権限操作は監査ログに残す。

## 9. リリース前チェック

- メンターとメンバーのログインが成功する。
- 無効化されたアカウントでログインできない。
- メンター以外が管理操作を実行できない。
- 開発ログの開始、終了、AI評価待ち、承認待ちが動作する。
- 承認済みログだけがEXP、ランキング、ボス戦力に反映される。
- 不審ログと未完了セッションが確認できる。
- ボス戦が3ターン進行し、行動未選択と通信断を処理できる。
- 前に映す画面の文字サイズと状態表示が教室利用に耐える。
- AI評価失敗時に記録が失われない。
- WebGLビルドに秘密情報が含まれていない。
